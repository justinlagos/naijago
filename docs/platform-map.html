Gold marks revenue

A small gold square marks a screen carrying one of the four placements. The booking zone is drawn in a broken red outline because it carries none, though today that holds by placement rather than by a coded guard.

Teal is settled, red is stop

Teal marks a fact that is already true: confirmed, verified, admitted. Red marks a dead end the user has to be walked out of. Neither is decoration; both map to real components.

Arrows carry the transition

Every arrow is labelled with what actually happens on it. Routes are the hash routes the prototype ships, so you can open any box in the running build and see it.

Build it in this order

  1. Tokens and the six shared components. Everything else is assembled from them.
  2. Chrome. Ticker, header, footer, dock, dialogs, toast.
  3. Homepage. It exercises most of the component set in one go.
  4. Explore and faceting, then the experience detail screen.
  5. The auth wall, with intent replay. Before checkout, because every later flow depends on it.
  6. Checkout, the hold, three rails and all four failure states together. The failures are not a follow-up ticket.
  7. Pass, offline caching, gate. The service worker is the promise, not a nice-to-have.
  8. The calendar, then the account area, waitlist and plans.
  9. Partner console. Fewest users, most arithmetic, and it can wait.
  10. Advertising last: the four placements, then the self-serve funnel against a real ad server and payment rail.
